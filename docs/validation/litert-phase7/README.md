# LiteRT Phase 7 validation

This directory contains the immutable inputs and report contract for the
full-song LiteRT promotion gate. Phase 7 reports are evidence for one exact
combination of model artifact, contract, ABI, backend, execution profile, and
precision. A successful short-window probe is not a Phase 7 promotion result.

## Files

- `report-schema-v1.json` defines the required report identity and measurement
  fields.
- `thresholds-v1.json` freezes the numerical, lifecycle, audio, and resource
  gates before the device matrix is run.
- `fixtures-v1.json` identifies the local research fixtures by hash without
  copying model weights, full audio, or reference stems into Booming SS.
- `phase7-inputs-v1.json` will pin the exact app commit, catalog, model Release,
  runtime, APK hashes, and fixture references once the Phase 7 runner build is
  frozen.
- `s10-arm64-9662-window-cold-v2.json` records the first full-song S10 evidence
  summary. It remains pending promotion review: worker/cache correctness and
  one-LSB reference equivalence passed, while the frozen SNR gate did not and
  an 9662-specific resource policy still needs to be frozen. The HQ4-only
  resource budget must not be applied to 9662 retroactively.

Reports must be generated by the Phase 7 host/instrumentation runner. Existing
LiteRT window probes and the Phase 5 cache runner remain useful diagnostic
tools, but their reports cannot satisfy the production worker/player gate.

The host runner separates acquisition from execution. A full-song CPU run uses
the artifact retained by a preceding clean acquisition:

```powershell
.\tools\run_phase7_validation.ps1 `
  -Serial <serial> `
  -ProcessAbi arm64-v8a `
  -Stage worker `
  -KeepAppData `
  -CleanInstallScenario `
  -RunClass cold-session `
  -SourcePath <fixture-path> `
  -FixtureId coast_town_full_wav `
  -ExportCacheAudio
```

Use `-RunClass warm-session` for declared repetitions. `-ProcessorCount N`
overrides the processor count seen by the test-only CPU session factory so the
thread matrix can be reproduced without adding an application preference.
Window decoding is enabled by default; pass `-WindowDecode:$false` only when
the full-song fallback path is the explicitly measured case.
`-ExportCacheAudio` writes the worker's WAV and promoted FLAC stems plus a
SHA-256 manifest under the ignored `build/phase7-validation` directory. These
local artifacts may be compared with the frozen desktop ORT references, but
must not be committed to this repository.

Use `-Stage lifecycle` with the short fixture to exercise pause/resume and
cancellation against the same production worker and cache coordinator. It
expects the preceding pinned acquisition and does not export full audio.

The local fixture source is the companion
[`MusicSourceSeparation`](https://github.com/WluhWluh/MusicSourceSeparation)
repository. Full audio and generated reference stems are intentionally kept
outside this repository; reports retain hashes and reproduction instructions.
