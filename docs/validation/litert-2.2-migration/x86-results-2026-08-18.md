# API 26 x86 Validation Record

Date: 2026-08-18

This record closes the hosted GitHub Actions x86 product-gate experiment for
the LiteRT 2.2 migration. It does not change the GitHub product policy: 32-bit
x86 remains selectable for experimental CPU source separation, with ordinary
runtime/model allocation failures exposed to the user.

## Passing Local Path

The persistent local `Medium_Phone` API 26 x86 AVD was configured with:

- 4 GiB guest RAM;
- `dalvik.vm.heapsize=384m` at boot; and
- the downloaded `2.2.0-bss.2` x86 CPU runtime and `uvr_mdxnet_3_9662` model.

Two fresh product-shaped runs passed through the real GitHub runtime/model
providers, bound remote process, JVM `TensorBuffer` MDX execution, completed
two-stem cache publication, playback-cache opening, and cleanup. The logged
second run completed in 18.667 seconds: runtime install 3.462 seconds, model
download/install about 7.5 seconds, and separation/cache verification about
6.1 seconds. The earlier clean run completed in 22.018 seconds.

The local path is the retained x86 execution evidence. It is an experimental
qualification result for this exact AVD and model/runtime tuple, not a general
native-managed x86 support claim.

The decisive diagnostic from `32103643366` was:

```text

stage=runtime-download-complete:Installed
```

The hosted runner also reported that hardware acceleration was unavailable
and launched QEMU with `-accel off`. This makes it unsuitable for a long
real-model x86 product gate. The failed hosted runs do not invalidate the two
passing local runs, and do not justify an app-side x86 restriction.

## CI Decision

The `litert-x86-product` GitHub Actions job and its diagnostic helper are
removed. GitHub CI continues to build the x86 split/universal APKs and verify
their native/runtime inventories, but it no longer performs x86 emulator
source-separation inference or claims x86 product execution from hosted CI.

Future x86 product retesting must use the persistent local API 26 AVD (or a
real x86 device) with the frozen 4 GiB / 384 MiB environment and the real
GitHub delivery path. Release notes retain the concise limitation that
32-bit x86 and high-memory models may fail depending on device memory layout.
