## Screen-off observation

The same APK, installed model, CPU settings, source, and decode setting were
started with the S25 display asleep:

- device state was `Wakefulness=Dozing`;
- app process remained alive with `oom_score_adj=0`;
- active PSS was approximately 934.4 MiB, later approximately 911.1 MiB;
- mapped-region samples were 3,868 and 3,851;
- no `SourceSeparationProcessing` wake lock was present; and
- the run had not completed when the 304-second host timeout expired.

The display was then woken and the abandoned instrumentation was force-stopped.
No terminal worker report was committed because the host-side instrumentation
command had timed out.

This is a baseline result, not a new defect introduced by process isolation.
The current processing lease protects playback waiting for cache; a standalone
full-song worker does not independently own a screen-off CPU lifetime. Phase 2
must preserve this behavior, and the later independent-background phase must
address it explicitly rather than attributing it to Binder or LiteRT.

## Frozen gates

`thresholds-v1.json` freezes correctness, timing, total-memory,
idle-remote-memory, playback, process-death, and x86 repetition gates before a
remote result is reviewed. A later threshold revision requires a separate
documented rationale and cannot retroactively turn a failed run into a pass.
