# Downloadable LiteRT CPU runtime: Phase 1 validation

Date: 2026-07-31

## Device

| Field | Value |
| --- | --- |
| Device | Samsung Galaxy S25, `SM-S9310` |
| Android | 15 / API 35 |
| Process ABI | `arm64-v8a` |
| Runtime artifact | LiteRT `2.1.5-bss.2` |
| Release | `downloadable-runtime-v2.1.5-bss.2-exp.2` |
| Application code | `05cdcf15` |

## Procedure

1. Build `githubDebug` and its AndroidTest APK from the application source.
2. Install both APKs on the clean debug package.
3. Provision the pinned `arm64-v8a` CPU ZIP with
   `tools/install_litert_cpu_runtime.ps1`.
4. Run `LiteRtPackagingSmokeTest`.
5. Run `SourceSeparationInferenceProcessDeviceTest`.

The provisioning tool verifies the Release ZIP, component manifest, native
library byte size, and SHA-256 before copying `libLiteRt.so` and
`manifest.json` into the app-owned `no_backup` runtime directory. The source
separation `Application` loads that path before initializing its Koin graph.

## Results

| Test | Result |
| --- | --- |
| `appDoesNotPackageLiteRtNativePayload` | Pass |
| `installedCpuRuntimeRunsSmallModel` | Pass |
| `validateBoundServiceStartup` | Pass |
| `reconnectsAfterIdleRemoteProcessDeath` | Pass |
| `acknowledgedRecycleRequiresAFreshProcessIncarnation` | Pass |

The installed CPU component successfully ran the dynamic-shape add smoke
model. The packaging test found no `libLiteRt.so` or
`libLiteRtClGlAccelerator.so` in the APK and no class-loader-resolved copy.
The process tests confirmed a separate source-separation process, a fresh
generation after explicit recycle, and reconnection after remote process
death.

This record covers the S25 `arm64-v8a` path only. It does not close the
destructive replacement/version-switching cases or the API 26/API 29,
`armeabi-v7a`, `x86_64`, and pure `x86` matrix.
